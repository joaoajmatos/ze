# CF-14 doc deltas (System One kit + loop residue)

Floor note: CF-16 applies these and deletes this folder.

## Design notes

- `ze_agents/system_one.py` now holds the shared judge helpers: `surface_block(settings, name)`,
  `parse_bar(value, name, *, event)`, `valid_noul(answer, *, unit_range=True)` and
  `valid_choice(answer, options=None)`. Each surface keeps its own `decide()`, `build_state()`,
  questions and config dataclass. The six `build_state` functions share a name, not logic.
- Edge-case note (Maestro accepted, tested in `test_routing_judge.py`): `valid_noul` rejects a bool score everywhere. `ze_core.routing.judge` used to
  accept one (a JSON `true` read as 1.0). Skills and routing pass `unit_range=False` and the fact
  judge too, so out-of-range scores behave as before. The fact judge's biography Noul used to need
  only `noul is not None`; a NaN or non-numeric score now also gives `invalid_answer`
  (`test_fact_judge.py` covers bool and NaN).
- `ze_core.routing.judge.parse_bar` is gone; import `parse_bar` from `ze_agents.system_one`.
  Bar-invalid log events are unchanged except the complexity bar, which now logs
  `complexity_bar_invalid` (it logged `routing_bar_invalid`).

## R-01 verdict (no code change)

The `loop_judge` "conversation" row is still live after 173, so it stays. The `user` state key is
used by corroboration (conversation turns can corroborate a suspected loop), and the 1,000-char cap
is used by the title writer (`extraction.py` calls `capped_text` / `supported_provenance` for
`conversation`). `DecisionKind` `create_declared` is also live: `intake.py` builds
`LoopGateDecision("create_declared", ...)` and `extraction.py` acts on it. `loop_judge.decide` never
returns it now, but the type is shared.
