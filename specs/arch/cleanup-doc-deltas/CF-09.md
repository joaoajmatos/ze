## Follow-ups outside CF-09

- A-21 option B (single static path): runtime would mount `<pkg>.api.routes.router` for each loaded plugin class and `ZePlugin.rest_routes()` would be retired. It needs a floor that owns `ze-plugin` and the plugins, and it changes behavior (a disabled ze-news would mount its routes today's `rest_routes()` withholds). CF-09 shipped option A: `rest_routes()` stays the runtime source; `mount_plugin_routers` raises `PluginRouteDriftError` at startup when a runtime router is absent from the OpenAPI export's set.
- A-20 for plugins: the plugin routers declare full `/api/v0/...` paths themselves, so they are the one set not mounted under the `api/v0` router. Making them relative needs edits in `ze-personal`, `ze-news` and `ze-calendar` (outside CF-09).
- The OpenAPI path order differs from before only in that `/api/v0/ui/manifest` now follows the other system routes; JSON content is otherwise identical.
