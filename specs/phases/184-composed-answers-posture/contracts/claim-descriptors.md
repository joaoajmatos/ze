# Contract: claim-bearing descriptors (`ze-components`)

Normative for FR-001 to FR-006 and FR-019. Python dataclasses in `ze_components`; the TypeScript types are generated by `make codegen` into `packages/ze-ui/src/generated/`.

## `ClaimPosture` (sub-type, `PRIMITIVE_SUB_TYPES`)

| Field | Type | Rule |
|---|---|---|
| `kind` | `"identity" \| "fact" \| "inference" \| "suspicion" \| "priority" \| "action_record" \| "feedback_record" \| None` | The `ClaimKind` value the owning record carries: `OpenLoop.claim_kind`, `Hypothesis.claim_kind`, `ClaimKind.PRIORITY` for goals and relationship items (what `PriorityView` scoring assigns them). `None` for subjects that are not claims (`workflow`, `held_write`): they are actions and decisions, and no claim record stands behind them. |
| `subject` | `"loop" \| "goal" \| "workflow" \| "hypothesis" \| "person" \| "held_write" \| "fact"` | What the record is. The client picks the glyph from `subject` + `kind` (goal → hollow diamond; `suspicion` → dashed; `inference` → half; `kind` null → no claim glyph, the subject's own mark; otherwise filled). |
| `ref_id` | `str` | The record id (UUID string; held writes use `request_id`). |
| `confidence` | `float \| None` | 0..1 from the record. `None` when the record has none (workflow, held write). |
| `confidence_from` | `float \| None` | The value before decay. Omitted until a store exposes it (phase 185 for loops). Never derived by guessing. |
| `source` | `str \| None` | Plain key of where the claim came from: the loop's inflow (`OpenLoop.provenance`, e.g. `user_declared`, `email`), `goal`, `workflow`, `correlation`. The client maps keys to words; raw keys are never shown. |
| `as_of` | `str \| None` | ISO 8601 UTC of the last evidence or update (`updated_at`, `confirmed_at`, `last_progress_at`, `fired_at`, `completed_at`). |
| `state` | `str \| None` | Closed per subject — loop: `suspected`, `active`, `drifting`; goal: `planning`, `active`, `awaiting_gate`, `paused`, `stuck`; workflow: `ok`, `failed`, `never_run`, `off`; held_write: `open`; hypothesis: `open`; person: `stale`; fact: none. |
| `slipped` | `bool` (default `false`) | True only for a drifting loop, a stuck goal, or a workflow whose last execution failed. |

`claim: ClaimPosture | None = None` is added to every class in `PRIMITIVE_TYPES` (`Col`, `Row`, `Text`, `Badge`, `Divider`, `Spacer`, `Button`, `ProgressBar`, `Table`, `Form`, `Connections`, `Steps`, `Chart`, and the three below where it is required on `ClaimCard`).

**Authoring rule.** Only code that has just read the owning record builds a `ClaimPosture`. `build_render_schema` omits `claim` at every depth; the `render_tool` wrapper pops a `claim` kwarg before calling the function and logs `render_tool_claim_dropped` with the tool name.

## New primitives (`PRIMITIVE_TYPES`)

### `Headline` — `type: "headline"`

| Field | Type | Rule |
|---|---|---|
| `text` | `str` | Uppercase; only `A–Z 0–9 · : -` and space; ≤ 40 characters (built by `headline_text()` which normalises and truncates). |

### `ClaimCard` — `type: "claim_card"`

| Field | Type | Rule |
|---|---|---|
| `title` | `str` | The record's title (loop title, goal title, workflow name, held write's first effect phrase + summary, person name). |
| `claim` | `ClaimPosture` | Required. |
| `span` | `4 \| 6 \| 8 \| 12` (default 4) | Canvas width hint; the Assemble canvas uses it (phase 187). |
| `lines` | `list[str]` | Up to 3 plain lines, no raw enums (e.g. "Drifting since Tuesday: no reply from Ana", "Next: draft the landing page"). |
| `readouts` | `list[Readout]` | Up to 4 `{label, value, tone: "default" \| "live" \| "hot"}` with values already formatted ("due in 3 d", "0.74", "2/5", "failed 2 h ago"). |
| `progress_done`, `progress_total` | `int \| None` | Goals only. |
| `actions` | `list[CardAction]` | `{label, intent, ref_id}`; `intent` ∈ `confirm_loop`, `drop_loop`, `approve_held_write`, `deny_held_write`, `approve_gate`, `open`. |
| `tone` | `"default" \| "cream" \| "hot" \| "dotted"` | Derived (below), never chosen per call site. |

Client mapping of intents (FR-019, phase 187 keeps it): `confirm_loop` → `confirmLoop(ref_id)`; `drop_loop` → `dropLoop(ref_id)`; `approve_held_write` / `deny_held_write` → `decideHeldWrite(ref_id, approve|deny)`; `approve_gate` → `action` frame `goal:approve:<ref_id>` (the payload `goals/executor.py` already issues for the gate push); `open` → navigate to the record by `claim.subject` + `ref_id`.

### `ClaimTimeline` — `type: "claim_timeline"`

| Field | Type | Rule |
|---|---|---|
| `title` | `str` | e.g. "Past 7 days to next 7". |
| `entries` | `list[TimelineEntry]` | `{title, claim, due_at: str \| None}`; `due_at` = loop `drift_deadline`. Sorted by `due_at`, nulls last. |
| `days_before`, `days_after` | `int` (default 7, 7) | Window. |
| `span` | `4 \| 6 \| 8 \| 12` (default 12) | |

## Tone derivation (`claim_tone(claim, needs_user)`)

1. `claim.slipped` → `hot`.
2. `needs_user` (held write, open gate) → `cream`.
3. `claim.kind in (suspicion, inference)` → `dotted` (a null kind never matches).
4. otherwise `default`.

A suspected loop in a decisions answer is `dotted` (rule 3 before nothing else applies; `needs_user` is false for suspicions because the One Alarm Rule and DESIGN.md show a suspicion as a question in a dashed frame). Coral never marks a gate, a held write or a suspicion.
